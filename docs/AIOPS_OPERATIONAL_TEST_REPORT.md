# AIOps 운영 오류 6종 — 실제 AWS 통합 시험

시험일: 2026-10-29

**최종 상태: 합성 오류 6종 모두 AI 응답 처리와 SNS 게시 성공. 실제 이메일 수신 사진은 추가 대기.**

처음에는 알림 한도 20회 중 15회를 사용한 상태라 5종을 먼저 검증했습니다. 사용자가 notification_limit=30을 직접 적용한 뒤 마지막 TLS 사례를 완료했습니다. Terraform 적용/삭제는 사용자가 수행했으며, 시험 중 운영 서비스나 카운터를 임의 변경하지 않았습니다.

## 시험 범위

운영 서비스를 고장 내지 않고 실제 백엔드 CloudWatch 로그 그룹의 전용 스트림에 합성 ERROR를 기록했습니다. CloudWatch 구독 → Lambda → DynamoDB → OpenAI → SNS 경로를 확인하며, 실제 앱 장애 재현/복구 시험과 구분합니다.

모델은 gpt-6-luna, 추론 강도 none입니다. 사용자가 요청한 6~8종 중 서로 다른 6종을 선택했습니다. 실제 이메일 수신 사진은 사용자가 추후 제공하며 현재 SNS 게시 상태와 수신 여부를 구분해 기록합니다.

```text

1. 요청 발생 시각의 애플리케이션 로그에서 JDBC 예외의 원인 체인을 확인하세요. 연결 시간 초과면 DB 상태와 네트워크 경로를 점검하세요.
2. DB의 상태·연결 수·연결 거부 지표를 같은 시각에 확인하세요. DB가 비정상이거나 한도에 도달했다면 해당 지표와 이벤트를 추가 조사하세요.
3. 비밀값을 출력하지 않고 애플리케이션의 DB 주소·포트·TLS 설정과 배포 변경 여부를 대조하세요. 불일치가 있으면 변경 이력과 실제 설정을 확인하세요.

4. 점검 대상 / 추가로 필요한 정보

- 점검 대상: 데이터베이스 연결 및 상태 지표

- 추가 확인: stack이 비어 있어 세부 예외와 실패 지점을 판단할 수 없습니다.

추정과 확인을 구분하세요
원인은 후보이며 AWS 리소스를 직접 조회하거나 변경하지 않았습니다.
```

기술적 가설과 점검 순서는 입력 근거에 부합합니다. 실제 DB 장애 원인을 맞혔다는 뜻은 아닙니다.

## 해석과 제한

- SUCCESS는 구조화된 응답 처리를 통과했다는 뜻이며, 원인 후보의 정답률 100%를 뜻하지 않습니다.
- 정성 검토는 입력 근거와 설명의 일치·안전한 점검 순서·불확실성 표시를 평가합니다. 실 장애 근본 원인 확정과 구분합니다.
- SNS 게시 성공과 실제 이메일 수신은 별도입니다. 사진이 도착하기 전까지 수신 완료로 표시하지 않습니다.
- 테스트는 실제 AWS 호출을 사용했습니다. Lambda/CloudWatch/DynamoDB/SNS/OpenAI 비용이 발생할 수 있으며 청구액은 별도 확인해야 합니다.
- 기존 429 두 건은 크레딧 부족으로 소급 확정하지 않습니다. 이번에는 충전 이후 새 요청의 결과를 기록합니다.
- Terraform 적용/삭제, 운영 DB/키/보안 그룹 변경이나 일일 카운터 초기화는 시험 중 수행하지 않았습니다.


## 최종 한도와 다음 작업

시험 종료 후 DynamoDB 조회 결과 AI 시도는 **10/10회**, 알림 시도는 **21/30회**입니다. 이전 실패 시도도 AI 한도에 포함돼 있으며 이번 6종은 모두 SUCCESS였습니다. 오늘의 AI 시도 여유는 없고 UTC 일자 갱신 전 추가 오류는 기본 안내로 처리될 수 있습니다. 한도를 다시 늘리거나 초기화하지 않았으며 추가 테스트 입력을 보내지 않았습니다.

이메일 사진을 받으면 각 사례의 오류 코드·요청 번호에 맞춰 첨부하고 실제 받은편지함 수신 여부를 확인할 예정입니다. 현재 사진 자리는 수신 확인을 의미하지 않습니다. 사진을 공개 저장소에 넣기 전 이메일 주소·계정 식별자·개인정보가 노출되는지 확인합니다.

### 분석 품질에서 확인한 점

- 6종 모두 입력 코드/예외에 맞는 범주의 원인 후보와 점검 순서를 제시했습니다. DNS와 TLS는 같은 EXTERNAL_API_ERROR 분류 안에서도 설명을 다르게 구성했습니다.
- 근거가 부족한 HTTP 500을 특정 코드 버그나 DB 장애로 확정하지 않았습니다.
- 실제 리소스 조회/복구 완료를 주장하지 않았고, 비밀번호나 리소스 식별자를 만들어내지 않았습니다.
- 모델에는 개인정보 최소화를 위해 요청 번호·관측 시각을 보내지 않습니다. 따라서 일부 응답에서 추가 요청한 정보가 이메일 하단의 추적 정보와 중복됩니다. 이는 향후 표시 방식에서 다듬을 부분입니다.
- 실제 운영 장애의 근본 원인을 입증하는 시험이나 자동 복구 시험은 아니며, 정확도 100% 또는 운영 SLA를 주장하지 않습니다.
