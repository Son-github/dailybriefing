## 카카오맵 설정 ON 이후 재검증

2026-10-20 17:18 KST 재조회: 현재 `.env`의 REST 키와 실행 컨테이너 키가 일치함을 값 노출 없이 확인했습니다. 장소 검색 HTTP 200 / 15개, 주소 변환 HTTP 200, 서울역→강남역 대중교통 HTTP 200 / 후보 중 최단 소요시간 경로 1개 / 31분을 수신했습니다. 이 소요시간은 당시 공급자 응답이며 이후 운행 상황에 따라 달라질 수 있습니다.

한글 장소 검색이 0개였던 추가 원인은 검색어를 인코딩한 URI 문자열을 HTTP client가 다시 인코딩한 것입니다. 완성된 URI를 직접 전달하고 한글·공백·+ 검색어 회귀 테스트를 추가했습니다. Docker 이미지에 반영했고 장소/주소/경로의 한글 완료 로그도 확인했습니다.

REST API 재조회에서는 현재 실패가 없습니다. 브라우저 지도 SDK 자체가 표시되지 않는 경우에는 별도로 JavaScript 키와 해당 키의 SDK 도메인(`http://localhost:5173`, 사용하는 운영 도메인)을 확인하세요. JavaScript 키를 바꾸면 frontend 재빌드가 필요합니다. 계정 첫 활성화 앱의 무료 쿼터 여부와 추가 앱/초과 사용 조건은 [공식 사전 설정 안내](https://developers.kakao.com/docs/ko/kakaomap/common#prerequisite)를 확인하세요. 이 점검에서 결제/유료 설정은 변경하지 않았습니다.

## 로그 확인

```bash
docker compose logs -f backend
```

정제된 API 응답까지 완료된 시점에 `날씨 데이터 가져오기 완료`, `환율 데이터 가져오기 완료`, `공휴일 데이터 가져오기 완료`, `뉴스 데이터 가져오기 완료`를 기록합니다. 실패는 성공으로 기록하지 않으며 샘플은 `(샘플 · 외부 API 미호출)`을 표시합니다. provider_http의 RECEIVED는 전송/JSON 수신, data_fetch의 SUCCESS는 내부 모델 변환 후 완료입니다.

오류 응답에는 안전한 공급자 이름·공급자 HTTP 상태를 details로 전달합니다. 화면에는 오류 원인·코드·요청 번호와 해결 안내를 표시합니다. DNS/TLS/접속 거절을 실제 시간 초과와 구분합니다. TLS 검증을 끄거나 무조건 재시도하지 않습니다.

검증: backend 단위 테스트 30개 + PostgreSQL 통합 테스트 10개, frontend 테스트 29개, 관련 Desktop/Mobile 브라우저 테스트 6개 통과. lint/typecheck/build 및 Docker image build/health check 통과. 실제 LIVE 재조회에서 날씨·환율·공휴일·뉴스는 성공했고 카카오는 서비스 비활성화 오류를 재현했습니다. 자동화 브라우저 뉴스 테스트는 고정 응답으로 격리해 실제 API 쿼터를 사용하지 않도록 수정했습니다.
